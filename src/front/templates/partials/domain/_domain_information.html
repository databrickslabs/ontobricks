How the mapped triples (…_data) are stored. Materialized copies them into a clustered Delta table at build time. Views only creates a pass-through view over the Triple-Store Gateway instead — nothing is duplicated and queries always read live source data.
In Views only mode, builds are near-instant and no storage is consumed, but every graph query re-runs the mapping SQL against your source tables. Inferred triples (reasoning, cohorts) always keep their own Delta table, and Graph Analytics materializes a temporary snapshot for the duration of a run.

Dual Knowledge Graph

When you build the Knowledge Graph, OntoBricks creates two complementary representations:

  • Triple-Store Gateway — a SQL VIEW in Unity Catalog that maps directly to your source data with no duplication. Used for Quality checks.
  • Graph Database — a Graph DB embedded graph for Graph Viewer exploration, GraphQL queries, and API access.
The Triple-Store Gateway VIEW is always created in the registry's catalog.schema. Its name is derived from the domain name and version (triplestore_<domain>_V<version>).
