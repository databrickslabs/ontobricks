Loading scenarios…

A scenario is a safe “what if”. You change a few facts on a copy of part of your knowledge graph, let your business rules react, and see what would change. Real data is never touched.

Energy example. “What if customer C-102 switched its contract to the Green tariff?” In the scenario, your rules may then flag C-102 as eligible for the green rebate and drop its old Standard plan discount. You see both effects before deciding anything in real life.

The journey of a scenario
Step 1: Choose what to copy (the scope)
  • One entity and its surroundings: for example customer C-102 plus everything up to 2 steps away (its contracts, sites, meters).
  • A cohort: a saved group, for example all customers fed by substation North-7.

Rules only see what was copied. If a rule needs a wider view (a total over all customers, say), widen the number of steps or use a cohort.

Step 2: Describe your what-ifs (three kinds of facts)
Step 3: Choose which rules react

Tick the same rule families you use on the live graph (business rules, IF-THEN rules, graph reasoning…). They run on the sandbox after your facts, so you see the knock-on effects, not only the facts you typed.

Step 4: Run and read the results

A scenario goes Draft → Running → Ready (or Failed with a message). The Results tab lists what appeared and what disappeared, and tells you whether each change is your fact or was inferred by a rule (hover to see which rule).

Step 5: Compare with the real (live) graph

Go to Simulation → Compare, pick a Ready scenario and press View difference. One picture shows the scenario laid over today’s live data:

  • Live graph (inferred) compares against today’s data including rule results; Live graph (asserted only) compares against the raw data only.
  • Click any box or link to see exactly what changed, and which rule produced it.
  • Compare uses today’s live data. If the live graph changed since your run, re-run the scenario to refresh it.
Step 6: Ask a business question (Evaluate)

On the same Compare page, the Evaluate tab asks one question to both worlds, for example “Which customers are eligible for the green rebate?”. You get the live answer, the scenario answer, and an AI commentary on the difference. Open report bundles the facts, the Compare picture and both answers; Export PDF saves it to share with stakeholders.

More scenario ideas
  • What if this meter is decommissioned? Remove its links and see which sites lose monitoring.
  • What if a site’s consumption doubles? Set the new value and see which tariffs or alerts your rules trigger.
  • What if this customer signs a second contract? Add the contract and check bundle discounts or risk scores.
Technical details
1. Scope — which slice of the graph

Choose how far the sandbox reaches (capped at 5 000 entities / 250 000 triples):

  • Entity neighbourhood — one entity URI and N hops of neighbours (default 2).
  • Cohort — members of a saved Cohort Discovery rule.

Only triples whose subject is in that set are copied (attributes and outgoing relationships). Rules later only see what was copied — widen hops or use a cohort scope if a rule needs a broader view.

2. Copy into the sandbox

In-scope triples are copied into an isolated store (<graph>__sim_<scenario id> on Lakebase/Delta, or a marker-labelled Neo4j graph). That copy is the before picture. Overlay keys remember every (subject, predicate) the sandbox owns, including predicates emptied by Remove.

3. Hypothetical facts (operations)

Facts are applied in list order, inside the sandbox only:

  • Set — replace every value of a predicate on a subject (e.g. a new credit score).
  • Add — assert an extra triple; existing values are kept.
  • Remove — retract one exact triple.

Subjects, predicates, and objects can be existing entities/attributes or new hypothetical ones (wizard + optional “Propose facts” from natural language). Extra entities pulled in by a fact are copied from live with one neighbour hop so rules can attach related meters, contracts, etc.

4. Reasoning phases

Tick the same engines as Knowledge Graph → Inference (Simple rules, graph reasoning, Complex / IF-THEN rules, OWL 2 RL). They run against the sandbox after facts are applied; conclusions are written into the sandbox too. If IF-THEN is ticked and rules cannot run, the scenario fails instead of finishing as ready with zero inferences.

5. Results (sandbox before vs after)

After a successful run the scenario is ready. Results list triples that appeared (your fact vs inferred — hover for the rule) and triples that disappeared. Counts are exact; long lists are capped for display. Statuses: draft, running, ready, failed. Purge drops the sandbox after-picture but keeps the scenario as a draft; delete removes the scenario and its sandbox.

6. Compare with the live graph

Open Simulation → Compare. Pick a ready scenario and a live source (inferred or asserted only), then press View difference. One overlay graph uses the same scope as the run:

  • Nodes — grey unchanged, amber modified (attributes/types/links), green added in sandbox, red removed from live.
  • Links — grey unchanged, green added (fact or inferred), red removed/overwritten.

Click a node or edge for details. Counters are exact; the drawing prioritises changes (about 400 entities / 1 500 links). Unlike Results (before vs after of the same sandbox), Compare also reflects what the live graph did since the run — re-run the scenario to refresh the sandbox if live has moved on.

7. Evaluate (same Compare page)

The Evaluate tab asks Graph Chat the same question against live and the sandbox. When both answers succeed, a business-insights agent comments on the difference. Open report builds a printable summary (facts, Compare metrics/graph if you already ran Compare, both answers, analysis). Export PDF uses the browser print dialog.

Isolation & backends
  • The sandbox store refuses writes outside simulation tables — runs cannot touch the built graph or its caches.
  • Needs a supported graph backend (Lakebase / Lakehouse / Neo4j) and a registry-saved context.
  • New domain versions copy scenario specs as drafts; sandboxes are not copied — run again on the new version.
